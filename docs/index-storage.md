# 扫描索引

全量扫描保留每个可读文件和目录的元数据，不通过抽样、限制目录数量或删除错误记录来缩小索引。索引保留元数据和受限的项目说明，不保存完整文档或会话正文；AI 总结仍需显式操作。

- 新扫描写入独立临时索引。完成后关闭写入，在支持的 macOS 文件系统上无损压缩，由系统解压并逐字节核对，再原子替换上次完整结果。
- 已发布索引 `index-v4.sqlite3` 以只读方式打开。设置、清理预览、授权和逐文件记录保存在独立的 `user-state.sqlite3`；目录重新计量仅保存事务性增量，复用子目录汇总并核对跨目录硬链接，不展开整个压缩索引。
- 下一次完整扫描自动替换旧快照及对应增量。停止、失败或空间不足保留已发布结果；启动时只回收具有本应用所有者记录且所属进程已经退出的临时索引。
- 界面显示索引实际分配的磁盘空间，包括设置库与 WAL。压缩后的文件逻辑长度可能明显大于实际占用。
- 遍历时维护覆盖少量文件的索引，只在结束时批量建立两个密集索引，避免为每个小索引重读整张元数据表。
- 批量读取元数据遇到缺失属性、不支持的文件系统或过大的单目录时，回退到逐文件读取；权限失败和扫描期间变化仍列为未读取，不计作零。

读取异常会在扫描结束后自动核实；诊断页可按权限、失效路径、云端超时和格式筛选，并重试补读。恢复的目录补扫后同步大小与分类，原始原因与补读结果保存在小型设置库；参见[读取诊断](read-recovery.md)。

任务使用单调时钟；等待时继续计时，完成时包含原子发布与缓存提交。

旧索引会在后台升级，迁移前先完成 WAL 检查点；新旧版本使用不同索引文件名，避免旧版重新创建的空设置覆盖新版历史。首次转换需要临时压缩文件的空间；完整扫描仍需要未压缩工作索引的空间，并保留磁盘余量。未知或不支持压缩的文件系统沿用普通索引，不影响预览与确认清理。

验证使用 `cargo test --locked --manifest-path native/Cargo.toml`、`node --test native/tests/progress.test.mjs`、`scripts/test-native-smoke.py`、`scripts/test-native-parity.py`、`scripts/test-native-recovery.py`。`scripts/benchmark-native-scan.py` 在同一批临时文件上轮换新旧二进制，核对完整路径、大小、归类与关联结果指纹。

原生 type-4 decmpfs 资源叉布局参考 brkirch 的 [afsctool（GPL-3.0）](https://github.com/jrk/afsctool/blob/d81014e9b6df9582da2a523e89b06523af517496/afsctool.c)。编码实现位于 `native/src/fs_compression.rs`，不附带第三方可执行文件；本仓库继续采用 GPL-3.0-only。
