# 读取诊断与补读

完整扫描结束后自动复查本次记录的读取异常。「读取诊断 → 核实并补读」可在授权、同步或目录变化后再次核实；仅处理当前扫描已记录的路径，不扩大清理范围，也不执行清理。

| 分类 | 核实依据与处理 |
| --- | --- |
| 权限不足 | 保留实际 `EACCES` / `EPERM`，区分文件权限拒绝与 macOS 隐私或系统保护。单凭 `EPERM` 无法确定具体 TCC 服务或保护机制。 |
| 路径失效 | 核实 `ENOENT` / `ENOTDIR` / `ESTALE`；启动磁盘扫描先核对实际数据卷路径及目录身份，避免无根目录别名导致误报，保留原始原因和本次状态；消失的路径不当作已成功读取。 |
| 云端超时 | 云目录使用独立进程，10 秒无响应后终止本次读取并重试一次；仍不完整则保留超时。不会主动下载云端占位文件的内容。 |
| 格式异常 | 先检查 SQLite 文件头；空文件和仅含一个绝对路径的备份记录不再按数据库解析。未知格式与损坏数据库仍标为异常。 |
| 已补读 | 重新可读的目录全量补扫；单个文件通过父目录补扫同步。原子更新占用、文件分类及异常计数；不跟随链接、不跨卷。 |

补读在 App 后台进程运行，沿用 App 的系统授权；文件系统检查有独立进程超时边界，任务可停止。不会自动提权、修改文件权限或绕过 macOS 保护。部分系统目录即使授予完整磁盘访问仍可能受限。授权后可以再次补读。

已发布的压缩索引保持只读，补读写入事务性增量和诊断记录。下一次完整扫描替换旧快照及旧诊断记录。文件内容不会发送给模型；AI 判读仍禁用文档读取，AI 总结仍需用户明确选择与确认。

验证：`native/tests/read_recovery.rs` 检查分类、补扫、计数、重启与重复核实；`native/tests/overlay.rs` 检查错误增量的回滚、持久化、合并与压缩索引不膨胀；`scripts/test-native-recovery.py` 使用打包进程和临时受限目录核实真实 API。
