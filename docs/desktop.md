# 桌面版

界面以米白、暖浅灰与象牙白构成纸张层次，使用轻微的本地纤维纹理和纸面明暗；陶土橙（`#B5532F`）只强调操作与选中状态。字体与 Tempo 相同，使用 SF Mono / Menlo 与中文苹方等系统字体，不依赖在线字体加载。

应用图标、侧栏标识与加载图标共用 `public/icon.svg`；macOS 构建时自动导出 PNG 与 ICNS，保持配色一致。

ICNS 资源按内容摘要命名，构建结束后刷新应用注册，避免 Finder 与 Dock 在图标更新后继续显示旧缓存。

[项目首页](../README.md) · [English](desktop.en.md)

项目清理统一展示所有项目，可筛选「含 AI 记录」；原 AI 专项的按项目入口自动跳转至该筛选。切换筛选会清空勾选与预览，避免误清理隐藏项目。

## 运行要求

- macOS 12 或更新版本；目前在 Apple Silicon Mac 上验证，Intel 构建尚未验证。
- 源码开发需要 Git、Rust 1.88+ 稳定版和 Xcode Command Line Tools（`xcode-select --install`）。Rust 安装见[官方说明](https://rust-lang.org/tools/install/)。
- 首次构建需要联网下载 Cargo 依赖。已构建的 `.app` 不依赖 Node.js 或 Rust 安装。

```sh
git clone --recurse-submodules https://github.com/Ray-hola/Minorminor-Rust.git
cd Minorminor-Rust
./scripts/run-native.sh
```

`start.command` 是相同入口。如果 `vendor/mole/` 为空，运行 `git submodule update --init --recursive`。

## 使用

扫描时顶部常驻区显示步骤、文件数、占用、耗时和当前路径；失败会持续显示原因。扫描前读取磁盘总量与可用空间，以已用空间估算扫描量；有同范围完整历史时优先采用历史占用。顶部显示「预计进度」，为归类、目录计量与模型检测预留后续进度，全部完成才显示 100%。文件数、步骤计数和实际占用仍单独显示；估算不代表精确剩余耗时。[功能迁移与验证清单](native-parity.md)。

选择扫描范围，完成扫描后展开项目或工具目录，查看文件夹和文件大小。默认审阅缓存与日志；会话和记忆需要单独启用。预览内再次勾选具体文件，默认移到废纸篓，也可单独明确确认永久删除。通过逐文件记录核对原路径、目标和处理状态。

空间清理提供 Mole 四种预览；从 clean 预览生成可勾选范围清单，或单独确认整次 Mole clean 的永久清理。整次命令按上游完整规则执行，范围不等同于可选清单。项目和清单的预览与确认操作保持可达。

AI 判读支持工具、逐文件清单和 Mole 清单，分批审阅并合并结果；模型连接可启用扫描时的候选结构识别。本地模型页显示详情与运行状态。项目、工具、诊断、建议、清单和逐文件记录均可导出 JSON / CSV；设置中可导入和查看 Web 历史。

界面侧栏提供简体中文和 English。切换会重载界面并清空未确认的勾选，后台任务继续运行；语言选择随应用记录保存。文件名、正文、项目介绍、模型回复和原始命令输出保留原文。

未识别用途、凭据、数据库及其 WAL/SHM、模型和依赖等内容保留。近期文件、身份已变化、正在使用或未通过保护检查的文件会跳过；不会移动项目根目录或清空废纸篓。移动后需重新扫描更新占用。可依据逐文件记录从废纸篓手动移回，不承诺 Finder 的「放回原处」。

AI 判读只接收经你审阅的元数据，读取文档和调用工具的权限固定禁用。AI 总结只对你点选并确认的资源抽读：最多 12 个内容文件、160 个条目、32 个目录、3 层深度、48,000 字符；文档抽取和压缩读取另有限制，预览显示实际覆盖。模型不会自动勾选或清理。

## 记录与权限

记录保存在 `~/Library/Application Support/com.minorminor.desktop/`，包含 SQLite 索引、设置和逐文件操作记录；API Key 只在进程内存。服务只监听 `127.0.0.1` 的临时端口，扫描期间关闭窗口只隐藏界面，点击 Dock 图标可恢复；「停止」或应用菜单「退出」会停止任务，其他类型任务仍随窗口关闭而停止。应用不会自动申请管理员权限。

扫描错误会区分权限拒绝、路径失效和其他读取错误。需要查看受 macOS 保护的目录时，可在「设置 → 文件访问权限」打开系统设置，自行决定是否授予完全磁盘访问权限，再重新扫描。

本仓库只维护 Rust + WebKit 桌面应用。[Node.js Web 版](https://github.com/Ray-hola/Minorminor)在独立仓库维护，记录、接口与清理流程分别演进。

## 验证与构建

```sh
cargo test --locked --manifest-path native/Cargo.toml --no-default-features
cargo check --locked --manifest-path native/Cargo.toml
./scripts/build-macos.sh
node --test native/tests/progress.test.mjs
python3 scripts/test-native-smoke.py
python3 scripts/test-native-parity.py
```

冒烟测试仅在临时目录生成模拟项目，验证打包进程、扫描同步、目录大小、Mole 保护、废纸篓记录和重扫，不处理真实用户文件。

扫描优化复用 SQLite 语句和脱敏正则，按关联路径查找项目，并合并目录占用与错误计数的汇总。每次仍完整遍历所选范围，没有新增文件数、目录深度上限或忽略规则，也不会根据上次索引跳过文件。权限拒绝、路径消失等读取失败仍保留诊断；清理前的身份检查和确认流程保持原样。

可用临时样例对比两个构建：

```sh
python3 scripts/benchmark-native-scan.py --baseline /path/to/previous/Minorminor --runs 3
```

该脚本核对全部文件、目录和逻辑大小，并比较两个版本的占用、硬链接、分类、项目、工具及会话关联索引；仅在临时目录创建样例，不扫描或清理个人文件。只测文件扫描和本地归类，禁用可选 AI 网络请求。

2026-10-19 本机 release 构建对比：61,204 个文件、2,007 个目录和 1,200 条会话关联，同一批样例交替运行各三次，耗时中位数从 18.754 秒降至 2.158 秒（约 8.7 倍）；六次索引比较一致。这是本地样例的结果，实际耗时随磁盘、云端目录和权限状态变化，不代表所有 Mac 的固定提速。

两项 Python 3 测试验证打包后的应用及本地模拟 AI / Ollama 服务。

生成 `dist/Minorminor.app`，只包含当前机器架构。构建脚本复制固定版本 Mole、保护脚本和许可文件，并验证 ad-hoc 签名；这不等于 Apple Developer ID 签名或公证。[v0.2.1 预览包](https://github.com/Ray-hola/Minorminor-Rust/releases/tag/v0.2.1)仅提供 Apple Silicon 版本，未提供通用二进制或公证安装包。

文案位于 `public/locales/en.js`；界面使用 `tr` / `ui` 翻译固定文案，文件路径与内容作为插值保留，不对整个 DOM 执行翻译。

旧版本记录缺少估算总量时，会用已读取的磁盘容量恢复预计百分比；重启或执行其他任务后，仍保留最近扫描结果与百分比。桌面应用以 `Minorminor-Rust/dist/Minorminor.app` 为准。

窗口重新获得焦点时会同步后台任务；扫描范围随最近一次扫描恢复，后台启动的数据卷扫描不会显示成用户目录扫描。手动选择下次扫描范围后，普通进度刷新不会覆盖选择。

扫描成功后先刷新总览中的扫描占用和读取错误，项目、工具明细随后加载，避免结果已完成但总览仍显示「待扫描」。

百万级目录的安装候选、记忆、目录和硬链接查询使用专用索引；首次升级在可见的扫描准备阶段完成，不阻塞窗口初始化。目录按路径倒序汇总，子目录始终先于父目录，无需对整批长路径按长度排序。安装识别、记忆关联和项目占用更新也会报告当前处理路径。

项目占用按项目逐条读取索引并汇总，避免反复对百万级文件身份做临时表排序；硬链接、分类数量与扫描期间移动产生的重复身份仍按原有口径去重。

百万级文件扫描的项目归类与首次明细加载仍可能等待数分钟。百分比是估算值；部分数据库操作期间路径和计数可能暂时不变。全量扫描指遍历所选卷内可访问的范围，不跟随符号链接或跨卷；受权限或云端超时影响的未读取部分不会当作零占用。

## 贡献与同步

维护者 Ray-hola 决定功能范围、合并与发布。修改功能时运行上面的检查，同步双语说明；测试只使用临时样例。提交按功能组织，说明实际改动和验证结果。

推送前核对差异、目标远端和分支，排除 `.runtime/`、`dist/`、`native/target/`、密钥与个人扫描数据。Mole 固定提交与 `UPSTREAM.json` 保持一致。推送后核对远端提交及对应 Actions 运行；正式发布另行准备版本、变化说明和签名状态，不将 Actions 产物标为公证安装包。共享提交用 `git revert <提交>` 恢复，不改写已推送历史。

反馈请附 macOS 版本、芯片架构、复现步骤和错误码，提交前隐去个人路径与文件内容；不要在公开 Issue 上传原始扫描数据库或 API Key。

## 文件授权与索引空间

首次扫描前提供集中授权入口，显示正在运行的 `.app` 路径，并打开完全磁盘访问设置与应用所在位置；最终开关由用户在 macOS 中确认。引导记录不代表权限已授予，不读取 TCC 数据库或代替用户点击开关。源码启动脚本改为构建并打开固定路径的 `.app`，GUI 使用单实例锁，避免重复启动重置扫描。相同构建、相同路径的普通重启可沿用系统授权；ad-hoc 构建变更或应用换位置后仍可能需要重新授权，稳定 Developer ID 签名尚未提供。

索引写入使用数据目录所在卷的可用空间，每批检查并预留 256 MiB；不足时停止，不将部分扫描发布为完整结果。项目归类每批最多更新 2,000 条，避免一次事务生成巨量 WAL。完成扫描及失败后回收多余快照；中断后启动应用也会在后台回收，保留最近完整结果、设置与清理记录。

设置与空间不足提示提供「回收临时索引」和「索引存储」。占用与可复用空间分开显示：旧数据库的空闲页可供下次扫描复用，不能等同于已释放磁盘空间。新数据库支持增量归还空页；旧库可选择「重建索引」，单独确认后移除可重新生成的扫描缓存、压缩数据库，保留设置与清理记录，不处理用户文件。空间极少、其他程序占用空间或长时间读取锁仍可能令回收失败；不会删除 WAL 文件来伪造释放。

索引使用紧凑存储：扫描编号与父目录只保存一份，条目使用整数引用；文件身份的八个字段无损压缩，保留完整路径、纳秒时间戳和硬链接信息。旧索引在后台逐批迁移、逐条核对，完成后原子切换；迁移中断可重试，原完整扫描仍保留。设置中的「优化索引」会回收旧快照并压缩旧数据库，空间足够时自动用校验后的紧凑副本替换，保留设置与清理记录；空间不足会显示原因。新索引采用增量回收，后续空闲页可直接归还磁盘。优化不缩小扫描范围，也不删除用户文件。
